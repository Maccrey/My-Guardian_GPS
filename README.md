# Watch Over - 안전한 위치 공유 및 귀가 알림 서비스

## 개요

Watch Over는 학부모와 같은 보호자가 자녀의 위치를 실시간으로 확인할 수 있는 위치 공유 서비스입니다. 사용자 간의 상호 동의 기반으로 작동하여 프라이버시를 존중하면서도 안전을 보장합니다. 귀가 알림, 긴급 연락 등의 안전 기능을 제공합니다.

## 프로젝트 상태

### ✅ 현재 구현된 기능

#### 사용자 인증 및 계정 관리

- 로그인 및 회원가입 시스템 (이메일/비밀번호 인증)
- 비밀번호 찾기 기능
- 회원 탈퇴 기능

#### UI 및 화면

- 다국어 지원 기능(한국어/영어) - 개인정보 처리방침, 이용약관, 앱 정보 페이지
- 홈 화면 및 기본 UI 구성
- 설정 화면 (테마, 알림, 위치 서비스 등 설정)
- 정보 제공 화면 (개인정보 처리방침, 이용약관, 앱 정보)

#### 메시지 기능

- 메시지 모델 및 서비스 기본 구현
- 메시지 목록 및 상세 화면 구현
- 읽지 않은 메시지 뱃지 표시 기능

  - 읽지 않은 메시지가 있는 대화에 시각적 표시 (배경색, 글꼴 강조)
- 로컬 메시지 저장 및 Firebase 연동
- 백그라운드에서 새 메시지 알림 표시

#### 위치 공유 기능

- 실시간 위치 공유 시작/중지 기능
- 사용자 친화적인 위치 공유 버튼 UI
- 위치 공유 상태에 따른 버튼 텍스트 변경 ("위치 공유 시작" ↔ "위치 공유 정지")
- 위치 공유 시작/종료 시 수신자에게 알림 전송

- Firebase Firestore를 사용한 위치 데이터 저장
- 백그라운드에서도 작동하는 위치 추적 서비스
- 다양한 오류 상황에 대한 폴백 메커니즘 구현

## 위치 공유 기능 구현 가이드

### 기본 아키텍처

위치 공유 시스템은 다음과 같은 컴포넌트로 구성되어 있습니다:

1. **서비스**: `LocationSharingService` 클래스 (`lib/services/location_sharing_service.dart`)

   - 실시간 위치 공유 관리
   - 위치 데이터 Firebase 업로드
   - 위치 공유 상태 관리
   - 위치 공유 시작/종료 알림 및 메시지 전송

2. **모델**:

   - `SharedLocation` 클래스: 공유된 위치 정보 저장
   - `LocationMessage` 클래스: 위치 공유 관련 메시지 모델

3. **UI 컴포넌트**:

   - `LocationSharingButton`: 위치 공유 시작/중지 버튼 위젯
   - 긴급 연락처 상세 화면의 위치 공유 버튼 통합

4. **알림 시스템**:

   - `NotificationService`: 위치 공유 관련 로컬 알림 처리
   - 알림 탭 시 위치 추적 화면으로 이동 기능

5. **메시지 시스템**:
   - `MessageService`: 위치 공유 메시지 관리 및 상태 추적

### 구현된 주요 기능

#### 1. 위치 공유 기본 기능

- **실시간 위치 공유**: 선택한 연락처와 실시간으로 위치를 공유할 수 있는 기능
- **위치 공유 버튼 UI**: 공유 상태에 따라 텍스트와 색상이 변경되는 직관적인 UI
- **공유 상태 관리**: `isShareLocationActive` 메서드를 통한 공유 상태 확인 및 관리

#### 2. 위치 추적 메커니즘

- **Geolocator 패키지 활용**: 정확한 위치 정보 획득 및 실시간 업데이트
- **위치 정확도 최적화**: `LocationAccuracy.low` 설정으로 배터리 효율성 증가
- **타임아웃 처리 개선**: 위치 정보 획득 타임아웃 시간을 30초로 증가
- **폴백 메커니즘**: 타임아웃 발생 시 대체 메커니즘으로 위치 정보 획득
  - 마지막 알려진 위치 캐싱
  - 대체 타이머를 사용한 주기적 위치 요청
  - 기본 위치 제공 (위치 획득 실패 시)

#### 3. 위치 공유 알림 시스템

- **공유 시작/종료 알림**: 위치 공유가 시작되거나 종료될 때 상대방에게 알림 전송
- **FCM 푸시 알림**: Firebase Cloud Messaging을 통한 알림 전송
- **로컬 알림 백업**: FCM 토큰이 없는 경우 로컬 알림으로 대체
- **알림 탭 처리**: 알림을 탭하면 위치 추적 화면으로 이동

#### 4. 위치 공유 메시지 시스템

- **자동 메시지 전송**: 위치 공유 시작/종료 시 자동으로 메시지 전송
- **메시지 모델**: 위치 공유 메시지를 위한 `LocationMessage` 모델 구현
- **메시지 상태 관리**: 현재 진행 중인 위치 공유 상태를 메시지 데이터로 추적

### 기술적 개선 사항

#### 위치 공유 안정성 개선

1. **타임아웃 증가**: 위치 정보 획득 타임아웃을 10초에서 30초로 증가
2. **위치 정확도 조정**: `LocationAccuracy.medium`에서 `LocationAccuracy.low`로 변경하여 배터리 효율성 증가 및 타임아웃 감소
3. **폴백 메커니즘**: 타임아웃 발생 시 대체 메커니즘으로 위치 정보 획득
4. **마지막 위치 캐싱**: 위치 정보 획득에 실패한 경우 마지막으로 알려진 위치 사용

#### 버튼 상태 관리 개선

1. **ID 매핑**: `userId`와 `contactId` 간의 일관된 매핑 구현
2. **상태 확인 개선**: `isShareLocationActive` 메서드 개선으로 모든 항목 검사
3. **MessageService와 통합**: 두 서비스를 통해 위치 공유 상태 확인

#### 알림 시스템 구현

1. **알림 채널 관리**: 위치 공유 전용 알림 채널 구현
2. **알림 페이로드**: 위치 공유 정보를 담은 알림 페이로드 구현
3. **알림 탭 처리**: 알림 탭 시 적절한 화면으로 이동

### 사용 방법

#### 위치 공유 시작하기

1. 긴급 연락처 화면에서 앱 사용자를 선택
2. "위치 공유 시작" 버튼 클릭
3. 확인 다이얼로그에서 "시작" 선택
4. 상대방에게 위치 공유 시작 알림이 전송됨

#### 위치 공유 중지하기

1. 위치 공유 중인 연락처의 "위치 공유 정지" 버튼 클릭
2. 확인 다이얼로그에서 "중지" 선택
3. 상대방에게 위치 공유 중지 알림이 전송됨

### 문제 해결 및 디버깅

#### 위치 공유 상태 불일치 문제

- `userId`와 `contactId` 간의 불일치로 인한 버튼 상태 변경 문제 해결
- 로그 메시지 추가로 위치 공유 상태 디버깅 용이

#### 타임아웃 문제

- 위치 타임아웃 시 대체 메커니즘 구현
- 마지막 알려진 위치 정보 캐싱으로 지속적인 위치 제공

#### 알림 전송 문제

- FCM 토큰 없는 경우 로컬 알림으로 대체
- 다양한 오류 상황 처리 및 로깅

## 귀가 알림 기능 구현 가이드

### 기본 아키텍처

귀가 알림 시스템은 다음과 같은 컴포넌트로 구성되어 있습니다:

1. **서비스**: `HomeArrivalService` 클래스 (`lib/services/home_arrival_service.dart`)

   - 귀가 경로 추적 관리
   - 집 위치 등록 및 관리
   - 귀가 완료 감지 및 알림

2. **모델**: `HomeAddress` 클래스

   - 집 주소 정보 저장
   - 위도/경도 좌표 정보

3. **UI 컴포넌트**:
   - 홈 화면 귀가 추적 상태 배너
   - 귀가 알림 카드 (추적 시작/중지 버튼)
   - 집 주소 설정 화면

### 주요 기능

#### 귀가 경로 추적

1. 사용자가 귀가 버튼을 누르면 현재 위치부터 등록된 집 주소까지 추적을 시작합니다.
2. 백그라운드 서비스를 통해 앱이 닫혀 있거나 백그라운드 상태에서도 추적이 계속됩니다.
3. 위치 데이터는 주기적으로 업데이트되어 사용자의 이동 경로를 기록합니다.

#### 귀가 완료 감지

1. 사용자가 집 반경 내에 진입하면 귀가 완료로 판단합니다.
2. 귀가 완료 시 로컬 알림이 표시됩니다.
3. 귀가 상태는 Firebase에 기록되어 보호자가 확인할 수 있습니다.

#### 백그라운드 처리

1. Flutter Background Service를 사용하여 백그라운드에서도 위치 추적이 유지됩니다.
2. 앱의 라이프사이클 상태 변화를 감지하여 서비스를 적절히 관리합니다.
3. 배터리 최적화를 위한 위치 업데이트 간격 조정 기능이 있습니다.

## 메시지 기능 구현 가이드

### 기본 아키텍처

메시지 시스템은 다음과 같은 컴포넌트로 구성되어 있습니다:

1. **모델**: `Message` 클래스 (`lib/models/message_model.dart`)

   - 기본 텍스트 메시지, 위치 공유 요청, 위치 공유 등 다양한 메시지 유형 지원
   - Firestore와 통합을 위한 변환 메소드 포함

2. **서비스**: `MessageService` 클래스 (`lib/services/message_service.dart`)

   - 메시지 로컬 저장 및 Firebase 연동
   - 읽지 않은 메시지 수 관리 (상대방이 보낸 메시지만 카운트)
   - 대화 목록 및 특정 사용자와의 대화 조회
   - 백그라운드 메시지 알림 처리

3. **화면**:
   - `MessagesListView` (`lib/views/messages/messages_list_view.dart`): 대화 목록 화면
   - `MessageDetailView` (`lib/views/messages/message_detail_view.dart`): 특정 사용자와의 대화 화면

### 주요 기능

#### 오프라인 우선 접근법

메시지는 다음과 같은 순서로 처리됩니다:

1. 로컬 메시지 먼저 로드 (SharedPreferences 사용)
2. Firebase Firestore에서 실시간 메시지 구독
3. 로컬 메시지와 Firestore 메시지 병합 (중복 제거)

이를 통해 사용자는 인터넷 연결이 불안정하더라도 기본적인 메시지 기능을 사용할 수 있습니다.

#### 알림 배지 및 읽음 상태 관리

1. 읽지 않은 메시지가 있는 경우, 홈 화면의 하단 탭 바에 있는 메시지 아이콘에 배지로 표시됩니다.
2. 배지는 상대방이 보낸 메시지만 카운트합니다.
3. 메시지 목록에서 읽지 않은 메시지가 있는 대화는 시각적으로 강조됩니다.
4. 메시지 화면을 열거나 메시지를 읽으면 배지가 즉시 업데이트됩니다.
5. 백그라운드에서 새 메시지가 도착하면 로컬 알림이 표시됩니다.

## 알림 시스템 구현 가이드

### 기본 아키텍처

알림 시스템은 다음과 같은 컴포넌트로 구성되어 있습니다:

1. **서비스**: `NotificationService` 클래스 (`lib/services/notification_service.dart`)

   - 로컬 알림 관리
   - 알림 권한 요청 및 설정
   - 다양한 알림 유형 처리 (메시지, 귀가 완료 등)

2. **통합**: 다른 서비스와의 연동
   - `MessageService`: 새 메시지 알림
   - `HomeArrivalService`: 귀가 완료 알림
   - 앱 라이프사이클 관리와 연동

### 주요 기능

#### 로컬 알림

1. Flutter Local Notifications 패키지를 사용하여 구현
2. 알림 채널 설정 및 사용자 설정 반영
3. 알림 터치 시 적절한 화면으로 이동

#### 백그라운드 알림 처리

1. 앱이 백그라운드 상태일 때 새 메시지 확인
2. 백그라운드 서비스와 연동하여 알림 발생
3. 알림 중복 방지 및 그룹화 처리

## 기술 스택

### 프론트엔드

- **Flutter**: UI 프레임워크
- **GetX**: 상태 관리, 의존성 주입, 라우팅
- **SharedPreferences**: 로컬 데이터 저장

### 백엔드

- **Firebase**:
  - Firebase Authentication: 사용자 인증
  - Firestore: 데이터베이스

### 위치 서비스 및 백그라운드 처리

- **Google Maps API**: 지도 표시
- **Geolocator**: 위치 정보 취득
- **Flutter Polyline Points**: 경로 표시
- **Geocoding**: 주소 변환
- **Flutter Background Service**: 백그라운드 작업 처리
- **Flutter Local Notifications**: 로컬 알림 표시

```
lib/
├── main.dart              # 앱 진입점
├── models/                # 데이터 모델
│   ├── message_model.dart # 메시지 모델

├── services/              # 비즈니스 로직 및 서비스
│   ├── message_service.dart  # 메시지 서비스
│   └── auth_service.dart     # 인증 서비스
├── view_models/           # 뷰와 모델 사이의 중간 계층
├── views/                 # UI 화면
│   ├── messages/          # 메시지 관련 화면
│   │   ├── messages_list_view.dart  # 메시지 목록
│   │   └── message_detail_view.dart # 메시지 상세
│   └── settings/          # 설정 관련 화면
└── utils/                 # 유틸리티 함수
```

## 데이터 절약 모드 구현 가이드

### 기본 아키텍처

데이터 절약 모드는 다음과 같은 컴포넌트로 구성되어 있습니다:

1. **서비스**: `SettingsService` 클래스 (`lib/services/settings_service.dart`)

   - 데이터 절약 모드 상태 관리
   - 설정 저장 및 불러오기
   - 다른 서비스에 설정 적용

2. **UI 컴포넌트**:
   - 설정 화면의 데이터 절약 모드 토글 스위치
   - 데이터 절약 모드 정보 카드

### 데이터 절약 모드의 주요 기능

#### 1. 위치 서비스 최적화

- **위치 업데이트 간격 조정**: 위치 업데이트 간격을 더 길게 설정하여 데이터 사용량 감소
  - 일반 모드: 10초마다 업데이트
  - 절약 모드: 60초마다 업데이트

#### 2. 이미지 처리 최적화

- **캐싱 기간 연장**: 이미지 캐싱 기간을 길게 설정하여 재다운로드 빈도 감소
  - 일반 모드: 30일
  - 절약 모드: 60일
- **이미지 해상도 최적화**: 필요 시 이미지 해상도를 낮추어 데이터 사용량 감소

#### 3. 네트워크 요청 최적화

- **폴백 타이머 간격 조정**: 위치 추적 폴백 메커니즘의 타이머 간격 증가
  - 일반 모드: 일반 간격의 2배
  - 절약 모드: 일반 간격의 3배
- **배치 처리**: 가능한 경우 여러 요청을 묶어서 처리

### 절약 효과

데이터 절약 모드는 다음과 같은 절약 효과를 제공합니다:

1. **데이터 사용량**: 최대 70%까지 데이터 사용량 감소
2. **배터리 수명**: 위치 정확도 감소로 인한 배터리 사용량 감소
3. **서버 부하**: 서버 요청 감소로 서버 부하 감소

### 사용 방법

1. 설정 화면에서 "데이터 절약 모드" 토글 스위치를 활성화
2. 데이터 절약 모드 정보 카드에서 절약 효과 및 제한사항 확인
3. 앱을 계속 사용하면 자동으로 최적화된 설정 적용

### 구현된 최적화 기술

1. **요청 간격 조정**: 위치 업데이트 및 데이터 요청 간격 최적화
2. **데이터 크기 최소화**: 전송되는 데이터의 크기 최소화
3. **캐싱 강화**: 캐싱 기간 연장 및 캐시 우선 사용
4. **배터리 효율성**: 위치 서비스 정확도 조정으로 배터리 효율성 향상
